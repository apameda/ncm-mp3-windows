# 1.0.0 测试记录

日期：2026-10-15。构建机：macOS Apple Silicon，Node.js 25.2.1。

## 已完成

- `npm test`：42 项通过，0 失败，0 跳过。
- 容器解析：分块还原 FLAC / MP3、中文与特殊路径、缺失或损坏的元数据、异常区块长度、封面预留空间、截断输入、拒绝覆盖和中途取消。
- 实际音频集成：使用本机 FFmpeg 8.0.1 生成短测试音频，再封装成 NCM 后转换；FLAC 输出 MP3 为 320 kbps / 44.1 kHz，标签保留且可完整解码。
- MP3 直接还原：转换前后音频包 SHA-256 一致；保持原测试音频的 128 kbps / 48 kHz，无二次有损编码。
- 文件安全：重名另存 `(2)`、已有成品和输入文件字节不变；损坏输入与取消均不发布最终 MP3；Windows 保留名和 UTF-16 长文件名边界通过。
- 主进程控制测试：模拟 Electron，验证递归添加、去重、并发启动拦截、失败后继续、准备期间取消、处理中取消和重试、成功项跳过、非法 IPC 来源拒绝。
- 界面测试：在 macOS 无头 Chrome 中使用模拟 API，验证添加、开始、操作锁定、进度、取消及重试、删除和清空、输出位置、音质参数、HTML 字符串按文本显示、小窗口无溢出。截图仅为示例队列。
- ZIP 写入器：中文路径、空文件、2 MB 分块二进制、解压后的逐字节一致与 CRC 校验通过。

复跑核心和控制流程测试：`npm test`。实际音频集成测试可用 `NCM_TEST_FFMPEG` 指定本机可运行的 FFmpeg。

复跑界面测试：见 `scripts/test-ui.cjs` 的说明（需要本机 Chrome 和 Playwright，可用 `CHROME_PATH` 与 `PLAYWRIGHT_MODULE_PATH` 指定路径）。

Windows 发行包使用经 SHA-256 核验的官方 Electron Windows x64 运行环境和 Gyan FFmpeg 9.0.2 Windows x64 二进制；构建脚本会检查包内所有 ZIP 条目完整性。

未在本机执行 Windows EXE。Windows 端的原生窗口、文件选择、实际 FFmpeg 9.0.2 子进程运行与首次启动，仍需在 Windows 10/11 x64 电脑验证。上述模拟测试与 macOS 音频测试不等同于 Windows 实机验收。
